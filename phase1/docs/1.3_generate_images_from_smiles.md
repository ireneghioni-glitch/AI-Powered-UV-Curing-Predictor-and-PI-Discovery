### Document Purpose

This document chronicles the development of the `generate_images.py` script, which represents the final step of Phase 1 of the MVP pipeline. It explains how we transformed SMILES strings into a ready-to-use dataset of molecular images, completing the data preparation phase and paving the way for Computer Vision feature extraction in Phase 2.

## 1. The Original Specification (What Phase 1 Required)

The MVP Technical Specification defines Phase 1 as:

> **"SMILES Ingestion**: Load known molecules (e.g., Benzophenone: `O=C(c1ccccc1)c2ccccc2`) using the **RDKit** cheminformatics library.
> **Image Generation**: RDKit converts the SMILES text string into a 2D pixel grid of a fixed size, for example, 224×224 pixels.
> **Channel Optimization**: Convert molecular drawings to grayscale, reducing memory footprint by 66%.
> **Data Augmentation**: Apply rotations (90°, 180°, 270°) to simulate spatial orientation independence."

The specification outlines a clear workflow:

    [SMILES String] 
        → RDKit (MolFromSmiles) 
        → RDKit (Draw.MolToImage) 
        → OpenCV (grayscale) 
        → Data Augmentation (rotations) 
        → Save (NPZ + metadata CSV)

This is exactly what `generate_images.py` implements.

## 3. Design Decisions and Reasoning

### 3.1 Why Grayscale?

| Aspect | RGB | Grayscale |
|--------|-----|-----------|
| Channels | 3 | 1 |
| Memory per image | 224×224×3 = 150,528 bytes | 224×224×1 = 50,176 bytes |
| Information | Color (unnecessary) | Shape (essential) |
| CNN compatibility | Works | Works |

**Decision**: Use grayscale because molecular structure recognition relies on shapes (bonds, rings, functional groups), not colors. This reduces memory usage by 66% without losing structural information.

### 3.2 Why 224×224 Pixels?

- Standard input size for many pre-trained CNNs (ResNet50, MobileNetV2, VGG16)
- Large enough to capture fine structural details
- Small enough to be computationally efficient
- Compatible with transfer learning pipelines

### 3.3 Why Rotations (90°, 180°, 270°)?

- Molecules are orientation-independent in 2D space
- Training the CNN to recognize rotated versions improves robustness
- Quadruples the dataset size (1 original + 3 rotations = 4×)
- Simple and physically meaningful augmentation (unlike flips, which could invert stereochemistry)

### 3.4 Why NPZ Format?

| Format | Pros | Cons |
|--------|------|------|
| PNG files | Human-readable, easy to inspect | Many files, slow to load, disk-heavy |
| NPZ (NumPy compressed) | Single file, fast loading, memory-efficient | Requires NumPy to read |
| NPY (uncompressed) | Fastest loading | Larger file size |

**Decision**: Use NPZ for optimal balance of speed and storage. The compressed format is ideal for the MVP dataset (208 images).

### 4.2 Core Function: smiles_to_grayscale()

    def smiles_to_grayscale(smiles):
        mol = Chem.MolFromSmiles(smiles)          # 1. SMILES → Molecule object
        if mol is None:
            raise ValueError(f"Invalid SMILES: {smiles}")
        img = Draw.MolToImage(mol, size=IMG_SIZE) # 2. Molecule → PIL Image (RGB)
        img_np = np.array(img)                    # 3. PIL → NumPy array
        gray = cv2.cvtColor(img_np, cv2.COLOR_RGB2GRAY)  # 4. RGB → Grayscale
        return gray

**Why this order?**
1. RDKit validates the SMILES first (if invalid, we fail fast)
2. RDKit generates the 2D drawing (no manual coordinate calculation needed)
3. OpenCV handles the grayscale conversion efficiently
4. The output is a NumPy array ready for CNN input

### 4.3 Data Augmentation: augment_rotations()

    def augment_rotations(image):
        h, w = image.shape
        center = (w // 2, h // 2)                 # Center of the image
        rotated = []
        for angle in [90, 180, 270]:
            M = cv2.getRotationMatrix2D(center, angle, 1.0)
            rot = cv2.warpAffine(image, M, (w, h), flags=cv2.INTER_LINEAR)
            rotated.append(rot)
        return rotated

**Why this works**:
- The molecule remains chemically identical after rotation
- The CNN learns that rotation shouldn't affect the prediction
- OpenCV's interpolation prevents pixelation

### 4.4 Processing Pipeline: process_molecule_row()

    def process_molecule_row(row):
        # 1. Extract data from row
        name = row['name']
        smiles = row['smiles']
        role = row['role']
        
        # 2. Skip invalid SMILES
        if pd.isna(smiles) or smiles is None:
            print(f"  Skipping {name}: no SMILES")
            return []
        
        # 3. Generate original image
        orig = smiles_to_grayscale(smiles)
        
        # 4. Create record for original image
        records = [{'image': orig, 'name': name, 'smiles': smiles, 'role': role, 'augment': 'orig'}]
        
        # 5. Add rotated versions
        for idx, rot in enumerate(augment_rotations(orig)):
            records.append({
                'image': rot,
                'name': name,
                'smiles': smiles,
                'role': role,
                'augment': f'rot{90*(idx+1)}'
            })
        
        return records

**Key features**:
- Error handling for invalid SMILES
- Metadata preservation (name, role, augmentation type)
- Returns 4 images per molecule

## 7. Key Lessons Learned

### A. Data Preparation Is Non-Negotiable

We couldn't jump straight to image generation without first obtaining SMILES strings. The separation of concerns (fetch_molecules.py for retrieval, generate_images.py for processing) made the pipeline more robust and maintainable.

### B. Error Handling Is Essential

Not all molecules will have SMILES available. The script gracefully skips missing entries and continues processing the rest, producing a usable dataset with minimal manual intervention.

### C. Simple Augmentation Is Powerful

Rotating molecular images by 90°, 180°, and 270° quadruples the dataset size with minimal computational cost. This significantly improves the model's ability to generalize without requiring additional experimental data.

### D. Consistent Image Sizing Matters

Using 224×224 pixels ensures compatibility with pre-trained CNNs like MobileNetV2 and ResNet50, enabling transfer learning in Phase 2.

### E. Metadata Preservation Is Critical

Storing the augmentation type, SMILES, and role alongside the images ensures traceability and enables downstream analysis (e.g., evaluating model performance per molecule type).

## 10. Final Script Code

The complete script is shown below for reference:

    import pandas as pd
    import numpy as np
    import cv2
    from rdkit import Chem
    from rdkit.Chem import Draw
    from pathlib import Path

    BASE_DIR = Path(__file__).resolve().parent
    DATA_DIR = BASE_DIR / "data"
    IMAGES_DIR = BASE_DIR / "images"
    IMAGES_DIR.mkdir(parents=True, exist_ok=True)

    INPUT_CSV = DATA_DIR / "molecules_PIs.csv"
    OUTPUT_NPZ = IMAGES_DIR / "molecular_images.npz"
    OUTPUT_META = IMAGES_DIR / "molecular_metadata.csv"
    IMG_SIZE = (224, 224)

    def smiles_to_grayscale(smiles):
        mol = Chem.MolFromSmiles(smiles)
        if mol is None:
            raise ValueError(f"Invalid SMILES: {smiles}")
        img = Draw.MolToImage(mol, size=IMG_SIZE)
        img_np = np.array(img)
        gray = cv2.cvtColor(img_np, cv2.COLOR_RGB2GRAY)
        return gray

    def augment_rotations(image):
        h, w = image.shape
        center = (w // 2, h // 2)
        rotated = []
        for angle in [90, 180, 270]:
            M = cv2.getRotationMatrix2D(center, angle, 1.0)
            rot = cv2.warpAffine(image, M, (w, h), flags=cv2.INTER_LINEAR)
            rotated.append(rot)
        return rotated

    def process_molecule_row(row):
        name = row['name']
        smiles = row['smiles']
        role = row['role']
        
        if pd.isna(smiles) or smiles is None:
            print(f"  [FAIL] Skipping {name}: no SMILES")
            return []
        
        try:
            orig = smiles_to_grayscale(smiles)
        except Exception as e:
            print(f"  [ERROR] Error processing {name}: {e}")
            return []
        
        records = [{
            'image': orig,
            'name': name,
            'smiles': smiles,
            'role': role,
            'augment': 'orig'
        }]
        
        for idx, rot in enumerate(augment_rotations(orig)):
            records.append({
                'image': rot,
                'name': name,
                'smiles': smiles,
                'role': role,
                'augment': f'rot{90*(idx+1)}'
            })
        return records

    def show_preview(images, meta, n=4):
        import matplotlib.pyplot as plt
        fig, axes = plt.subplots(1, n, figsize=(12, 3))
        for i in range(n):
            axes[i].imshow(images[i], cmap='gray')
            axes[i].set_title(f"{meta.iloc[i]['name']} {meta.iloc[i]['augment']}")
            axes[i].axis('off')
        plt.tight_layout()
        plt.savefig(DATA_DIR / "preview.png", dpi=100)
        print(f"   Preview saved to {DATA_DIR / 'preview.png'}")

    def main():
        print(f"Loading molecules CSV from {INPUT_CSV}")
        df = pd.read_csv(INPUT_CSV)
        print(f"Found {len(df)} molecules.")
        
        all_data = []
        for idx, row in df.iterrows():
            print(f"    [{idx+1}/{len(df)}] Processing {row['name']}")
            all_data.extend(process_molecule_row(row))
        
        images = np.array([rec['image'] for rec in all_data], dtype=np.uint8)
        meta = pd.DataFrame([{k: v for k, v in rec.items() if k != 'image'} for rec in all_data])
        
        np.savez_compressed(OUTPUT_NPZ, images=images)
        meta.to_csv(OUTPUT_META, index=False)
        
        if len(images) >= 4:
            show_preview(images, meta)
        
        print(f'\n✅ Done! Generated {len(images)} images.')
        print(f'   Saved to {OUTPUT_NPZ}')
        print(f'   Metadata saved to {OUTPUT_META}')

    if __name__ == "__main__":
        main()
